## 1.9.0
- **Mission Orchestrator (new)**: run a project-orchestration MISSION inside one Muse session. A mission is an ordered, stateful sequence of prompts the follow-up engine sends on each idle detection — the **GOLIVE READY — Project Orchestrator** ladder (CONTRACT: read the project's source of truth and declare the execution contract → AUDIT: gaps with evidence and a dependency graph → EXECUTE: the highest-priority READY item end-to-end with evidence, without stopping to ask → CONTINUE: refresh live truth, reconcile, next item → RELEASE GATE: exact-artifact readiness, no promote on RED → CONVERGE: GOLIVE READY verdict with the evidence chain, or an explicit blocker list) plus **AUDIT ONLY**, **FIX FINDINGS** and **RELEASE PREP**. The step advances **only on a verified send** — a blocked, refused, paused or dry-run attempt never advances and never logs; an active mission takes precedence over the rotating phrase prompts. Hard caps (12 steps lifetime / 3 cycles) end a mission with a silent stop and exactly one log line. Step directives ship in English (agent-facing); the popup's labels are localized in all 6 locales.
- **Mission popup surface**: a compact Missions pill on the Auto-follow-up row opens a full-popup sheet — enable toggle, the 4 missions with name/step-count/description, live `step n/N · cycle c` progress with the current step's text, **Send step now**, **Pause mission** (the same `pauseUntil`, no second pause concept) and the last completion; the new `mission` log kind renders in the log list.
- **Performance (measured, not claimed)**: the observer debounce is now **adaptive** — a mutation carrying a card/surface node sweeps immediately while generic mutations keep the trailing debounce. Measured with the repo's own harness (`scripts/bench/perf.mjs`): **detect → click 121.5 ms → 2.5 ms** median (independent re-run: 2 ms), **scan per sweep −55%** (13.9 → 6.45 ms), and **one storage write per action** instead of two (digest counters folded into the click flush). A single-query gate now short-circuits pages with no candidate card. No safety rail was weakened: the fast path changes *when* the sweep runs, never *what* may be clicked — proven by the unchanged dedup invariants (`n7count 1`, `n11count 1`, `denyCount 0`, `forbiddenHit []`) and a reverse-mutation falsification.
- **Speed benchmark + harness**: `scripts/bench/perf.mjs` (popup open→painted cold/warm, scan cost, detect→click, service-worker start/wake, storage writes, memory) with sourced targets and a recorded load-sensitivity caveat; `docs/ELITE_BENCHMARK_REPORT.md` carries the numbers. ## 1.8.0
- **Pause / resume**: pause all automation for 15 minutes, 1 hour or until tomorrow (next local midnight, floored at 1 h) with one control row; the row flips to "Paused until HH:MM" + Resume and returns automatically. Keyboard: `Alt+Shift+P` toggles a 15-minute pause or clears an active one. While paused the toolbar badge shows `||` and a one-shot alarm flips it back at expiry.
- **Dry-run mode**: log-only — every detection is recorded as `*-dry` and nothing is clicked, with a sticky banner so the state can never be mistaken for live. `Alt+Shift+F` triggers the follow-up send on the active muse.ai tab.
- **Allow-once**: prefer a one-shot "Allow once" option when the card offers it, so a broad standing grant is never chosen silently; falls back to the plain option when only one exists.
- **Topic + keyword rules**: an allow-list of topics and a block-list of keywords (20 shipped seed words, two-step reset) decide which approvals are automated; a blocked card is logged with its reason.
- **Stuck / error recovery**: an optional prompt fires when Muse reports working with no DOM activity for N minutes (default 10) or when an error clears — both off by default, both capped by the existing cooldown/rate rails.
- **Schedule window**: restrict automation to chosen hours and optionally to the active tab only.
- **Optional settings sync**: opt-in mirror of the settings subset (never logs, stats or counters) to `chrome.storage.sync`, write-through with a byte-accurate 8 KB per-item quota guard (UTF-8 bytes, not code units) and a surfaced warning when a write is rejected; local storage always wins on load.
- **Startup digest**: one notification when you return ("Since your last session: N clicks · N follow-ups · N blocked"), composed locally, counters reset only when it is actually shown.
- **3-step onboarding** for new and upgrading installs (enable → recommended dry-run → first follow-up combo), skippable, shown once.
- **Language switcher**: the popup UI language can be chosen manually (Auto (browser) / English / Tiếng Việt / 简体中文 / 日本語 / 한국어 / Español) instead of only following the browser locale — a real per-user override of `chrome.i18n` by loading the chosen locale's messages, applied live without reopening the popup.
- **Consent boundary — connector/credential surfaces are never automated**: cards that ask the user to connect an account or paste a token (e.g. a "Connector" card with a Connect button) are hard-blocked, logged with reason `connector`, and never clicked, even if an Allow-like pair appears inside them. Reported live by the owner and now covered by a FORBIDDEN fixture + reverse-mutation proof.
- **Quiet Luxury design pass**: token/contrast work verified in the rendered output (chart day bars 1.88/2.06 → 3.32/4.52:1; dark toggle ON-vs-OFF 1.85 → 4.83:1; all text pairs ≥4.5:1) plus a composition pass (one alignment column, real type tiers, split colour roles, corrected action hierarchy, browser-default artifacts removed, chart scale/legend) — `docs/QUIET_LUXURY_SPEC.md`, `docs/BRANDING.md`.
- **Store packet localized for v1.8** (vi / zh_CN / ja / ko / es descriptions updated, short descriptions verified ≤132 chars) and the compliance checklist refreshed; store screenshots re-rendered from the real UI.
- **Test & robustness**: the follow-up harness races were fixed at the source (engine state is now observable — the status ping echoes the in-flight send lock and the applied config), giving deterministic runs; `test/background-unit.mjs` (29 checks) and `test/lang-switch-e2e.mjs` (36 checks) added; every guard carries a reverse-mutation falsification record (`docs/ENGINE_V18.md` §8).
