## (b) Verified clean

1. **XSS via page-derived topic — `stats.js:89-92` (title attr + text node).** Holds. Both sinks checked against the exact `replace()` calls: the title attribute escapes every `"` and is double-quoted — a double-quoted attribute value can only be terminated by a literal `"`, and character references (`&quot;`) decode to data inside the value without re-entering the tokenizer, so entity smuggling cannot break out; `<`/`>`/`&` are inert inside a quoted attribute. The text node strips `[<>&]`, so neither a tag (`<`) nor an entity (`&`) can form. This is load-bearing: the probe shows a crafted card can place `"><img src=x onerror=alert(1)>` into `byTopic` verbatim (40-char fallback topic) — and it still renders inert.
2. **`popup.js` `renderLog` / `renderMini`.** `renderLog` (`:22-32`) passes every page-derived field (`at`, `kind`, `label`, `context`) through `esc()` (`:15-17`, escapes `& < > "`), including the class-attribute context. `renderMini` (`:39-57`) interpolates only computed day keys (`dayKeyOf`) and numeric values; the SVG coordinates are arithmetic. (Storage-tamper caveat → V3-4.)
3. **Regex safety (ReDoS / unbounded work).** `ON_MUSE` (`content.js:33`) is anchored with no nested quantifier. `MUSE_URL_RE` (`background.js:6`) measured on 80k–200k-char adversarial inputs: worst 3.9 ms, linear (each `(label\.)*` iteration consumes its dot, so backtracking cannot compound). `extractTopic` (`content.js:235`): `{2,40}` bounded class + one lookahead — 10,000 calls on a 240-char worst case = 109 ms total (~11 µs/call). `matchAll` input is capped at 240 chars by `doClick` (`:285`).
4. **ON_MUSE guard bypass set** (executed hostname table, `new URL(...).hostname` as Chrome's parser does): `muse.ai` ✓; `MUSE.AI` → parser lowercases → ✓; `www.muse.ai`/`evil.muse.ai` ✓ (subdomain scope accepted, prior R9); `xmuse.ai` ✗; `muse.ai.evil.com` ✗; `muse.ai.` (trailing dot) → hostname keeps the dot → guard **rejects, fail-closed**; `xn--muse-8fa.ai` and Cyrillic-homoglyph punycode ✗ (a punycode label can never be literally `muse`); `127.0.0.1.nip.io` ✗; ports are excluded from `hostname` (`muse.ai:8443` → `muse.ai` — still muse.ai's own host). `localhost`/`127.0.0.1` pass **by design**, but the shipped manifest (`manifest.json:13`) never injects there — only the e2e temp copy adds the localhost match (`e2e.mjs:44`). Caveat: the fingerprint attribute is set at `content.js:30` before the guard at `:33` — cosmetic ordering, no behavior (attribute already accepted as benign, prior R8/F14).
5. **Pruning correctness** (executed on the extracted shipped functions): `pruneKeys` 401 day keys → exactly 400 kept, oldest dropped (`2026-01-01` gone, `2026-01-02` kept); 25 months → 24; `pruneTopics` 101 → top-100 kept, smallest dropped, ties → 100 kept, `{a:2,b:2,c:1}` keep-2 → `{a,b}`. No off-by-one (`while > keep`; `slice(0, len-keep)`). Zero-padded keys → lexicographic == chronological (verified for day/month/year; `pad2` used in both key builders). Local-time keys are identical across content/background/popup/stats (all use `getFullYear/getMonth/getDate`). `byYear` is uncapped but bounded to 1 key per calendar year. Growth is bounded overall: topic ≤40 chars, `byTopic` ≤100, `byDay` ≤400, `byMonth` ≤24, log ≤50, queue ≤60.
6. **Storage write map / non-collision.** `content.js` writes `{log, stats, clickCount}` in a single `set` (`:270`); `popup.js` writes `{enabled}` (`:105`), `{minDelayMs}` (`:109`); `background.js`/`stats.js` never write. Per-key merge semantics mean the popup cannot clobber stats. Cross-content-script collisions → V3-2.
7. **`flushClicks` invalidation behavior** (`content.js:251-274`). If `chrome.storage.local.get` throws synchronously (dead context), the outer catch resets `clickFlushing` (`:273`); if `set` throws between get and set, the inner catch swallows it and `clickFlushing = false` still runs (`:270-271`). A dead context stops clicking entirely via `alive()`/`stopForever` (`:301-306`). The queue caps at 60 (`:278`) so nothing grows unbounded; a never-fired callback strands `clickFlushing=true` but the cap bounds the loss and the script is dead in that scenario anyway. No throw path found inside the callback body (sloppy-mode primitive writes are no-ops — executed; `Object.keys` accepts primitives).
8. **e2e `statsCheck` falsifiability — confirmed, with limits.** Fresh scratch profile **per run** (`e2e.mjs:50`: `maa-e2e-<pid>-<timestamp>` path) + fresh extension copy (`:39-46`), so `byDay[today]` starts at 0 and the `≥10` bounds are real, not accumulated. Wired into `pass` (`:284-285`). If recording breaks entirely → `byDay`/`clickCount`/`logLen` all 0 → RED. If `extractTopic` breaks → `byTopic['test-repo']` is 0 → RED, and `'test-repo'` is only producible by the repo-regex branch on card17's context (probe-executed: the fallback and URL branches cannot yield it). The fixture's 11 expected clicks give the `≥10` bounds a thin margin, but any single missing click already fails `missing`. Residual gaps → V3-7.
9. **Stale references & API surface.** No `logQueue`/`flushLog`/`log(` callers remain in `content.js` (only `console.log` at `:297`); the merged recorder replaced the old path cleanly. Grep across `extension/`: no `eval`, `new Function`, `fetch`, `XMLHttpRequest`, `sendBeacon`, `WebSocket`, `localStorage`, `storage.sync`, `onMessageExternal`, `externally_connectable`, `postMessage`. The only `innerHTML` sinks are `popup.js:23,56` and `stats.js:78,85,89` — all reviewed above. `stats.html` is an extension page opened via `chrome.runtime.getURL` from the popup — no `web_accessible_resources` needed.
10. **Message surface.** `content.js:359` listens for `{type:'sweep'}`; only the extension's own contexts can reach `onMessage` (cross-extension senders arrive at `onMessageExternal`, which is unused; web pages are excluded without `externally_connectable`). A `sweep` message grants nothing — the 1 s heartbeat sweeps anyway. A sender check would be defensive-only; none needed.
11. **Manifest.** `version 1.3.0` (`:4`), permissions unchanged `["storage","alarms"]` (`:8`), hosts `https://muse.ai/*` + `https://*.muse.ai/*` (`:9`), no CSP relaxation, no remote code, popup + icons wired. `chrome.tabs.query({url:[…]})` in the popup is permitted by the host permissions (no `tabs` permission needed for these URLs).
12. **Bounded work in charts.** `renderChart`/`renderMini` geometry stays inside the viewBox for the real ranges (day=14, week=12, month=12 bars; mini=7 × 38 px in 292 px); only corrupt-storage `byYear` key floods could overflow visually (cosmetic, tamper-only).
